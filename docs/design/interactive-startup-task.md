# dsh-Go 可自定义交互式启动动画任务书

> 本文供后续 Agent 执行。当前仅记录方案，不表示相关功能已经实现。

## 任务目标

为当前工作区的 Android 应用 dsh-Go 增加一种可自定义的交互式启动画面。

采用 **背景图片／视频＋透明动画图层＋可编辑文字与按钮＋分段播放与变速** 的方案。让普通用户通过选择素材、填写文字和设置点击节点，制作类似 [dsh-startup-screen](https://github.com/6shenhonghong9/dsh-startup-screen) 的互动开屏，无需编写代码。

交付应包含可运行功能、一个内置示例模板、设置内编辑与预览，以及相关验证。不能只交付视频播放器或不可交互的演示。

## 一、工作约束

1. 开工先阅读并遵守仓库的 [AGENTS.md](../../AGENTS.md)、[CONTRIBUTING.md](../../CONTRIBUTING.md) 和 [架构文档](../architecture.md)，按仓库要求检查工作区、同步基线，保留用户及其他任务的未提交改动。
2. 本任务以 Android 为验收平台。共享 Flutter 层改动须保持其他平台可编译，不擅自修改鸿蒙、iOS 的宿主启动行为。
3. 未经明确要求，不 commit、push、创建 PR 或发布。
4. 沿用现有启动架构、设置入口、媒体能力和性能偏好。确实存在能力缺口时，再引入依赖或原生通道。
5. 不直接携带参考项目中未经授权的第三方人声、音效、图片等素材。使用原创或许可明确的资源；复用代码时记录来源并保留许可。
6. 不建设通用视频剪辑器、任意脚本执行环境或复杂节点编辑器。

## 二、预期用户体验

用户进入现有“启动画面”设置，可以选择：

- 默认启动画面。
- 自定义图片或视频。
- **交互式启动画面**。

选择交互式画面后，可从内置模板开始，按步骤修改背景、文字、按钮、动画与速度，并立即预览。

必须提供一个“两次确认”的示例模板：

```text
品牌入场
    ↓ 自动
第一幕：背景与准星运动，显示“开始”按钮
    ↓ 点击
第二幕：展示身份卡，显示“确认”按钮
    ↓ 点击
扫描演出：准星加速、扫描线划过
    ↓ 自动
欢迎文字＋光晕／轻微色散
    ↓
启动层退出，露出应用页面
```

即使用户不导入视频，也应能使用内置绘制效果体验完整模板。

界面中的昵称、编号属于装饰内容，不代表身份认证或系统权限授权。默认文案使用“开始”“确认资料”“欢迎回来”等，不虚构安全核验。

## 三、核心实现模型

### 3.1 图层结构

| 图层 | 内容 | 实现要求 |
|---|---|---|
| 背景层 | 纯色、图片或普通视频 | 复用现有媒体能力，支持填满和完整显示 |
| 透明效果层 | 准星、扫描线、扫光、光晕 | 第一版优先用 Flutter 实时绘制，无背景遮挡 |
| 内容层 | 标题、副标题、昵称、编号、按钮 | 使用原生 Flutter 组件，支持修改与本地化 |
| 转场层 | 淡入淡出、轻微色散、揭幕 | 作用于指定图层，退出时露出真实应用页面 |

**透明动画图层不等同于透明视频。** 第一版必须提供内置透明绘制效果，不要求支持任意带 Alpha 通道的视频。不要默认普通 MP4 支持透明背景。

### 3.2 分段与交互

每个需要等待操作的步骤采用：

**入场 → 等待 → 出场**

- 入场：播放一次。
- 等待：循环背景或停留在最后一帧，同时允许透明效果继续运动。
- 出场：收到点击后，播放过渡并进入下一步。
- 自动步骤：按指定动画或媒体结束事件推进。
- 跳过：随时结束整段开屏。

不能通过无限放慢一段视频来模拟等待。等待必须有明确的循环或停留状态。

第一版采用固定顺序模板，允许编辑各步骤内容与支持的参数，不要求任意分支、条件表达式或拖拽时间轴。

### 3.3 变速

必须支持：

- 视频步骤设置基础播放速度。
- 内置准星等效果独立设置运动速度。
- 确认后内置效果平滑加速，再进入下一幕。

视频速度通过播放器实际支持的能力实现。合理限制范围，并通过设备验证决定是否支持连续变速；不能承诺所有解码器都能平滑变速。

视频速度、绘制效果速度和步骤推进应有清晰关系。不要使用与实际播放脱节的固定计时器判断视频已经结束。

第一版背景视频默认静音，不纳入旁白与 TTS 编辑功能，避免变速导致语音节奏异常。

## 四、编辑与预览

在现有启动画面设置中扩展编辑入口，不另建独立设置系统。

最低编辑项：

| 项目 | 用户可配置内容 |
|---|---|
| 模板 | 选择内置“两次确认”模板 |
| 外观 | 暖白／深色、强调色 |
| 各步骤背景 | 默认背景、图片、视频 |
| 文字 | 标题、副标题、昵称、装饰编号、按钮文案 |
| 等待方式 | 循环背景或停留末帧 |
| 速度 | 视频播放速度、内置效果速度 |
| 转场 | 淡出、光晕、轻微色散等有限预设 |
| 播放频率 | 每次冷启动／每天首次冷启动 |
| 预览 | 从头体验，支持正常点击和跳过 |

要求：

- 采用固定布局预设与安全区，不做任意拖动、缩放每个元素的自由画布。
- 素材由系统文件选择器导入，按现有媒体导入惯例保存，不能依赖易失效的临时路径。
- 保存前完成必要的素材与配置校验，失败时保留上一个可用配置并给出明确提示。
- 预览不启动或停止引擎，不修改正式启动的播放频率记录。
- 预览与正式启动复用同一套渲染及步骤逻辑。
- 已保存的图片／视频启动画面不因切换样式而被删除。

配置使用结构化数据保存，包含必要的格式版本、步骤、素材引用、文字、效果与速度参数。仅允许声明式配置，不执行导入的代码。

主题包导出、分享和任意步骤编辑不属于本次必要范围。

## 五、接入现有启动流程

开始实现前，重点阅读以下入口，确认最新代码中的实际行为：

| 入口 | 当前职责及本任务关注点 |
|---|---|
| [应用入口](../../app/lib/main.dart) | 首帧前的启动信息加载；避免增加重资源同步等待 |
| [应用外壳](../../app/lib/app.dart) | 全局启动层挂载，主题变化不能导致重复播放 |
| [启动控制器](../../app/lib/launch/launch_state.dart) | 系统交接、就绪、跳过、资源释放与退出策略 |
| [启动覆盖层](../../app/lib/ui/launch/launch_overlay.dart) | 渲染、手势、底层页面绘制优化 |
| [启动设置状态](../../app/lib/state/launch_screen_state.dart) | 当前自定义素材的管理方式 |
| [启动设置界面](../../app/lib/ui/settings/appearance/launch_screen_section.dart) | 样式选择、编辑和预览入口 |
| [根页面判定](../../app/lib/ui/shell/root_gate.dart) | 引导、首页与引擎自动启动 |

必须遵守以下行为：

1. **系统启动画面正常交接后，才开始完整交互。** 不把多步骤交互塞入 Android 系统 SplashScreen。
2. **应用初始化与引擎启动继续并行执行。** 点击“开始”不能成为引擎启动的前置条件。
3. **交互主题不因引擎提前就绪而突然消失。** 等待点击的步骤应按用户选择推进。
4. **交互主题取消“点任意位置跳过”。** 只有明确按钮推进，单独的跳过按钮和返回操作负责退出。
5. **跳过只结束演出。** 不取消引擎启动、不改变权限、不清除配置。
6. **动画进度与引擎状态分开。** 阶段条表达演出进度；只有真实状态确认后，才能显示连接成功。
7. **不无限等待引擎。** 演出结束后进入实际页面，必要时由已有页面继续呈现启动或连接状态。
8. **首次安装、升级和需要操作的引导优先。** 不用完整仪式遮挡必要流程；实际启动错误不能被动画长期挡住。
9. **后台恢复不重播。** 切到后台暂停媒体与效果，返回后不补播跳过的计时事件、不重复推进步骤。
10. 默认动画和现有图片／视频开屏继续保持原有行为。

实现中优先使用现有启动控制器管理外层生命周期，新主题只负责内部步骤。避免复制一套引擎状态机或启动流程。

## 六、性能与适配

- 第一版采用不透明背景，保留现有底层页面停止绘制的优化。不增加全屏实时磨砂。
- 静态底板、文字与动态效果分离；动画帧不应导致整个应用重建。
- 同时活动的视频解码器数量保持最小。若为切换预加载下一段，明确其生命周期和内存成本。
- 处理片段切换的黑帧、循环接缝与末帧保持问题，用真实设备观察，不只依据播放器 API 判断。
- 所有资源本地可用，不增加启动时网络依赖。
- 跳过、退出、预览关闭后释放播放器、动画控制器、计时器和监听。
- 适配竖屏、横屏、刘海、手势导航、大字体和长昵称，按钮触摸区域至少 48dp。
- 尊重系统减少动画设置及现有性能偏好：停止旋转、扫光、色散和强亮度变化，保留可读文字与必要操作。
- 以中端 Android 设备稳定 60fps 为优化目标；高刷新率表现以测量为准。

## 七、实施顺序

1. **检查架构与媒体能力**  
   确认现有播放器的循环、末帧保持、倍速与资源释放能力，识别确实需要补充的部分。

2. **完成独立可预览模板**  
   先用内置背景和实时效果跑通入场、两次确认、加速、扫描与揭幕，确保没有用户视频也可演示。

3. **加入素材与配置编辑**  
   接入图片／视频导入、参数保存、背景选择和变速。

4. **接入正式启动生命周期**  
   处理系统交接、引擎提前就绪、跳过、后台恢复和首次引导。

5. **验证与收尾**  
   检查最终 diff，运行适当测试与本地化检查，完成真机演示及性能观察。

各阶段持续推进；遇到播放器能力限制，给出有证据的最小实现调整，不用扩展任务范围来绕开问题。

## 八、验收要求

### 功能

- 可在设置中选择交互式开屏，修改内容、保存并在下次冷启动生效。
- 内置模板完整体现两次点击、循环等待、确认后加速、扫描与揭幕。
- 导入的视频能够按配置循环、停留或播放结束后推进。
- 用户任意时刻点击跳过，都能正常退出演出。
- 长时间不点击不会让等待背景意外结束，也不会不断创建资源。
- 连续点击只推进当前允许的一步，不跳过后续确认。
- 预览不会影响引擎或正式启动频率。
- 默认开屏与现有自定义媒体功能无回归。

### 状态与资源

- 引擎已运行、正在启动、未自动启动、远程主机模式均能正常进入应用。
- 首次安装、升级、错误页面不被新动画阻塞。
- 切后台、恢复、屏幕旋转、主题变化后，不重播、不重复推进、不泄漏资源。
- 素材无法读取时有明确提示及可用恢复路径，不出现永久黑屏。
- 动画中显示的真实运行状态来自已有状态源。

### 验证方式

- 对步骤推进、连续点击、跳过、配置读取与生命周期补充有实质断言的测试。
- 按仓库要求运行 Flutter 检查与相关测试。
- 界面文案中英文同步，并运行本地化生成和检查。
- 用 Android 真机验证冷启动、视频切换、变速、后台恢复及性能。
- 提供关键步骤截图或一段完整录屏。
- 未运行的检查明确说明原因，不将静态分析或模拟器结果写成真机通过。

4. 相对改动前的启动与流畅度观察；没有测量的数据不要编造。
